# Database Setup Guide

## Quick Start (SQLite for Development)

```bash
cd backend
npm install
npm run db:generate    # Generate Prisma client
npm run db:push        # Create dev.db with all tables
npm run db:seed        # Optional: load demo data (Alex Kamau, admin)
npm run dev            # Start API
```

That's it! The database file is `backend/dev.db` (auto-created by `db:push`).

## Production Setup (PostgreSQL)

### Option 1: Docker (Recommended)

```bash
cd backend
docker-compose up -d
```

The `docker-compose.yml` starts:
- **PostgreSQL 16** with healthcheck
- **API** that auto-runs `prisma generate` and connects to PostgreSQL

### Option 2: Managed PostgreSQL (Railway, Supabase, Neon, etc.)

1. Get a PostgreSQL connection string
2. Set `DATABASE_URL` in `.env`:
   ```
   DATABASE_URL="postgresql://user:pass@host:5432/geton"
   ```
3. Change `provider = "sqlite"` to `provider = "postgresql"` in `schema.prisma`
4. Run migrations:
   ```bash
   npx prisma migrate dev --name init
   npx prisma migrate deploy   # For production
   ```

## Generating Migration SQL (Production)

For a clean versioned migration history:

```bash
cd backend
npx prisma migrate dev --name init
# Creates: prisma/migrations/20260101000000_init/migration.sql
```

This generates the full SQL DDL (CREATE TABLE, CREATE INDEX, etc.) for all 13 models.

## Database Models

The schema includes 13 tables:

| Table | Purpose |
|---|---|
| `User` | Account, KYC level, wallet, credit score |
| `KYC` | National ID, M-Pesa, KRA PIN documents |
| `Loan` | Application + state machine (pending → fees-required → approved → active → repaid) |
| `ActivationFee` | Fee payments (processing, insurance, verification) |
| `LoanPayment` | Repayment history |
| `Transaction` | Universal transaction log (fees, disbursements, repayments) |
| `PaymentIntent` | STK Push tracking (Paystack) |
| `Notification` | In-app messages |
| `Device` | Logged-in devices |
| `RefreshToken` | JWT refresh tokens (revocable) |
| `AuditLog` | Sensitive action log for compliance |
| `WebhookEvent` | Incoming Paystack webhooks (for retry/audit) |

## Inspecting the Database

```bash
cd backend
npm run db:studio     # Opens Prisma Studio at http://localhost:5555
```

## Resetting the Database

```bash
cd backend
rm dev.db              # Delete SQLite file
npm run db:push        # Recreate from schema
npm run db:seed        # Reseed demo data
```

For PostgreSQL:
```bash
npx prisma migrate reset
```

## File Layout (Auto-Generated)

```
backend/
├── prisma/
│   ├── schema.prisma           # ← committed (the source of truth)
│   ├── seed.ts                 # ← committed
│   ├── migrations/             # ← generated by `prisma migrate dev`
│   │   └── 20260101000000_init/
│   │       └── migration.sql   # ← generated SQL
│   └── dev.db                  # ← generated SQLite file (gitignored)
└── node_modules/
    └── .prisma/                # ← generated Prisma client
        └── client/             # ← auto-generated types
```

## Why no migration files are committed

- **`dev.db`** — contains test data, regenerated every time
- **`prisma/migrations/*.sql`** — generated when you run `npx prisma migrate dev` for the first time
- **`node_modules/.prisma/client/`** — auto-regenerated by `prisma generate`

These are all listed in `.gitignore` so they don't bloat the repo.
